Dify나 n8n 노코드 툴을 사용해 Gemini API와 Claude API, Chat-GPT API를 연동하여 자동 토론 파이프라인을 만드는 구체적인 가이드라인을 알려줘.

다중 LLM 자동 토론 파이프라인 구축 가이드 (Dify / n8n)
1. 전체 아키텍처 개념
토론 파이프라인의 핵심 구조는 다음과 같습니다:

[주제 입력] → [라운드 1: 3개 LLM 동시 발언]
           → [라운드 2: 이전 발언을 컨텍스트로 반박/보완]
           → [라운드 N: 반복]
           → [심판/요약 LLM이 최종 정리]
           → [출력 (문서/슬랙/DB 저장)]
핵심은 "이전 라운드의 모든 발언을 다음 라운드 프롬프트에 누적해서 전달"하는 컨텍스트 누적(context accumulation) 로직입니다.

2. n8n으로 구현하기 (더 유연함 — 추천)
2-1. 노드 구성
Manual Trigger / Webhook
  → Set (토론 주제, 라운드 수 설정)
  → Function (토론 히스토리 배열 초기화)
  → Loop Over Items (라운드 수만큼 반복, Split In Batches 노드 활용)
      → HTTP Request (Gemini API)
      → HTTP Request (Claude API)
      → HTTP Request (OpenAI API)
      → Function (3개 응답을 히스토리에 append)
  → HTTP Request (심판 LLM 호출 — 최종 요약/판정)
  → Google Docs / Notion / Slack 노드 (결과 저장)
2-2. 각 API 호출 설정 (HTTP Request 노드)
Claude API 예시:

Method: POST
URL: https://api.anthropic.com/v1/messages
Headers:
x-api-key: {{ $credentials.anthropicApi }}
anthropic-version: 2023-06-01
Content-Type: application/json
Body (JSON):
json
{
  "model": "claude-sonnet-4-6",
  "max_tokens": 1024,
  "messages": [
    {
      "role": "user",
      "content": "주제: {{ $json.topic }}\n\n이전 토론 내용:\n{{ $json.debateHistory }}\n\n당신은 '찬성' 입장입니다. 위 내용을 반박하거나 보완하며 논지를 강화하세요."
    }
  ]
}
Gemini API 예시:

URL: https://generativelanguage.googleapis.com/v1beta/models/gemini-2.0-flash:generateContent?key={{API_KEY}}
Body:
json
{
  "contents": [{
    "parts": [{"text": "주제: {{ $json.topic }}\n\n이전 토론:\n{{ $json.debateHistory }}\n\n당신은 '중립/사회자' 입장입니다."}]
  }]
}
OpenAI(ChatGPT) API 예시:

URL: https://api.openai.com/v1/chat/completions
Headers: Authorization: Bearer {{API_KEY}}
Body:
json
{
  "model": "gpt-4o",
  "messages": [
    {"role": "system", "content": "당신은 '반대' 입장의 토론자입니다."},
    {"role": "user", "content": "주제: {{ $json.topic }}\n\n이전 토론:\n{{ $json.debateHistory }}"}
  ]
}
2-3. 컨텍스트 누적 로직 (Function/Code 노드)
각 라운드가 끝날 때마다 JavaScript 코드 노드에서:

javascript
const round = $input.first().json.roundNumber;
const geminiRes = $('Gemini API').item.json.candidates[0].content.parts[0].text;
const claudeRes = $('Claude API').item.json.content[0].text;
const gptRes = $('OpenAI API').item.json.choices[0].message.content;

const newHistory = $json.debateHistory + `
[라운드 ${round}]
Gemini(중립): ${geminiRes}
Claude(찬성): ${claudeRes}
GPT(반대): ${gptRes}
`;

return [{ json: { ...$json, debateHistory: newHistory, roundNumber: round + 1 } }];
2-4. 라운드 반복 처리
Split In Batches 노드로 라운드 수(예: 3~5)만큼 루프
또는 IF 노드로 roundNumber < maxRounds 조건을 걸고 루프백 연결
2-5. 최종 심판 단계
마지막에 별도 LLM 호출(예: GPT-4o 또는 Claude Opus)로:

"다음은 세 AI의 토론 전문입니다: {{ debateHistory }}
각 입장의 핵심 논거를 요약하고, 논리적으로 가장 설득력 있는 주장을 평가해주세요."
3. Dify로 구현하기 (더 간단, UI 중심)
3-1. Workflow 앱 생성
Dify 대시보드 → Create App → Workflow 선택
Start 노드에 입력 변수 정의: topic(토론 주제), rounds(라운드 수)
3-2. 모델 프로바이더 등록
Settings → Model Provider에서 Anthropic, Google(Gemini), OpenAI API 키를 각각 등록
3-3. 노드 구성
Start → LLM 노드(Gemini, 역할=중립)
      → LLM 노드(Claude, 역할=찬성, 이전 출력 참조)
      → LLM 노드(GPT, 역할=반대, 이전 출력 참조)
      → (Iteration 노드로 라운드 반복 감싸기)
      → LLM 노드(심판, 전체 히스토리 종합)
      → Answer 노드
Dify의 Iteration 노드를 사용하면 위 3개 LLM 호출 블록을 N번 반복하면서 배열에 결과를 축적할 수 있습니다.
각 LLM 노드의 프롬프트에서 {{#start.topic#}}, {{#llm_claude.text#}} 같은 변수 참조로 이전 노드 출력을 다음 프롬프트에 삽입합니다.
3-4. 프롬프트 템플릿 예시 (Claude 노드)
시스템: 당신은 토론에서 '찬성' 입장을 맡은 AI입니다. 감정적 표현보다 논리와 근거 중심으로 발언하세요.

사용자: 주제: {{#start.topic#}}
지금까지의 토론:
{{#iteration.debate_log#}}

위 내용에 대해 당신의 입장에서 반박 또는 보강 발언을 작성하세요.
4. 공통 설계 팁
항목	권장 사항
역할 고정	각 모델에 찬성/반대/중립(사회자) 등 역할을 프롬프트로 명확히 고정해야 토론이 산으로 안 갑니다
컨텍스트 길이 관리	라운드가 많아지면 토큰이 급증하므로, 매 라운드 전체 로그 대신 "직전 1~2라운드 요약"만 전달하는 방식도 고려
Rate Limit	3개 API를 순차 호출 시 지연 발생 — n8n은 병렬 실행(Merge 노드로 합치기) 가능, Dify는 기본 순차 실행
비용 관리	라운드 수 × 3개 모델 = 호출 수 급증. max_tokens을 500~800 정도로 제한 권장
결과 저장	n8n은 Notion/Google Sheets/Slack 노드로 바로 연동 가능, Dify는 Answer 노드 결과를 별도 API로 웹훅 전송 필요
API 키 보안	n8n은 Credentials 기능으로 키를 암호화 저장, Dify는 Model Provider 설정에서 관리 — 워크플로우 JSON export 시 키 노출 주의
5. 어떤 툴을 선택할지
빠르게 프로토타입 원하면: Dify (LLM 노드 UI가 직관적, Iteration 노드로 라운드 관리 쉬움)
세밀한 로직/외부 서비스 연동(Slack 알림, DB 저장, 병렬 처리) 원하면: n8n (Function 노드로 자유도 높은 커스텀 로직 가능)
두 툴 모두 무료 셀프호스팅이 가능하니, 간단한 3-라운드 토론부터 먼저 n8n이나 Dify 중 하나로 구현해보고 확장하는 것을 추천합니다. 더 구체적으로 어떤 툴을 쓸지 정해지면 해당 툴의 실제 JSON 워크플로우 예시도 만들어 드릴 수 있습니다.
